# N14 — A `pages` or `streamed` an endpoint cannot have

Error.

```wf expect=N14
type Post { id: String, title: String }
type FeedPage { posts: [Post], nextCursor: String? }

api Social(base: "/api") {
    get feed(after: String?) at "feed" -> FeedPage!
        pages .cursor(param: after)
}

page P(path: "/", title: "T", description: "D") {
    resource feed = Social.feed()
    Heading("Feed").h1
    for p in feed.items by p.id { Text(p.title) }
}
```

```text
error[N14]: `pages .cursor` on `Social.feed` says nothing of where the next page starts
 --> src/App.wf:5:5
  |
5 |     get feed(after: String?) at "feed" -> FeedPage!
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = help: Name it from a page: `next: p => p.nextCursor`
  = docs: https://webfluent.monzeromer.dev/errors/N14
```

```wf fixed
type Post { id: String, title: String }
type FeedPage { posts: [Post], nextCursor: String? }

api Social(base: "/api") {
    get feed(after: String?) at "feed" -> FeedPage!
        pages .cursor(param: after, next: p => p.nextCursor, items: p => p.posts)
}

page P(path: "/", title: "T", description: "D") {
    resource feed = Social.feed()
    Heading("Feed").h1
    for p in feed.items by p.id { Text(p.title) }
}
```

An endpoint may answer more than once for one read. It may answer a page
at a time:

- `pages .number(param: page)` asks for page 1, 2, 3 and stops at the
  first empty page;
- `pages .cursor(param: after, next: p => p.nextCursor)` asks for the next
  page with the cursor the last one gave, and stops when there is none;
- `pages .link` asks for the address the answer's `Link` header names
  `rel="next"` (RFC 8288), and stops when there is none.

Or it may answer a line at a time, `-> [Line]! streamed`, one JSON value
a line.

Either way a read of it holds a list: every page's items, or every line
so far. So each must say what it needs. The parameter the next page goes
in is one of the endpoint's, and the first call need not give it: it has
a default, or may be null. A page that is not a list itself says where
its items are, `items: p => p.posts`. A streamed endpoint answers a list.
Both are reads, `get`s: a write is sent once. And `for await` walks only
a streamed endpoint's lines.

**Fix:** Say what the style needs — the parameter, where the next page
starts, where a page's items are — or answer a list.
