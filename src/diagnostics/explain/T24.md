# T24 — `Map` written as a type

Error.

```wf expect=T24
page P(path: "/", title: "Prices", description: "D") {
    state prices: Map = { tea: 3, coffee: 4 }
    Heading("Prices").h1
    Text("Tea is {prices.tea ?? 0}")
}
```

```text
error[T24]: `prices` is written `Map`, which 7.0 took out of the language: it says nothing of the keys or what they hold
 --> src/App.wf:2:5
  |
2 |     state prices: Map = { tea: 3, coffee: 4 }
  |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  = help: Write a `type` with its fields, a dictionary `[String: T]`, or `Json` for JSON whose shape is open
  = docs: https://webfluent.monzeromer.dev/errors/T24
```

```wf fixed
page P(path: "/", title: "Prices", description: "D") {
    state prices: [String: Number] = { tea: 3, coffee: 4 }
    Heading("Prices").h1
    Text("Tea is {prices.tea ?? 0}")
}
```

A `Map` held anything under any key, so `prices.tae` read as nothing and the
page showed it. 7.0 says what a map is:

- **a record**, when its keys are known: `type Price { tea: Number, coffee:
  Number }` — a field it lacks is `T05`;
- **a dictionary**, when its keys are not known but what they hold is:
  `[String: Number]` — reading a key gives a `Number?`;
- **`Json`**, when it is JSON whose shape is open, matched or decoded where it
  is read.

**Fix:** write one of them. The editor's quick fix, `wf fix --code T24` and
`wf migrate` write `Json`; a record or a dictionary is better where you know
what it holds.
