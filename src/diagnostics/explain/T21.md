# T21 — A read's `match` with no `.failed` arm

Error.

```wf expect=T21
type User { name: String }

page P(path: "/", title: "T", description: "D") {
    resource users: [User] = http.get("/api/users")
    Heading("Users").h1
    match users {
        .loading { Spinner }
        .loaded(list) { Text("{list.length} users") }
    }
}
```

```text
error[T21]: this `match` on `users` has no `.failed` arm and no `else`, so a failed request shows nothing
 --> src/App.wf:6:5
  |
6 |     match users {
  |     ^^^^^
  = help: Add `.failed(e) { Alert(e.message).danger }`, or `else { … }`
  = docs: https://webfluent.monzeromer.dev/errors/T21
```

```wf fixed
type User { name: String }

page P(path: "/", title: "T", description: "D") {
    resource users: [User] = http.get("/api/users")
    Heading("Users").h1
    match users {
        .loading { Spinner }
        .failed(e) { Alert(e.message).danger }
        .loaded(list) { Text("{list.length} users") }
    }
}
```

A read is `.loading`, `.failed(e)` or `.loaded(value)`. A first load that
fails is `.failed(e)`; with no arm for it, the place stays empty and the
reader is never told. A `match` that misses `.loading` or `.loaded` is
[T15](T15.md).

**Fix:** `.failed(e) { Alert(e.message).danger }`, or an `else`. The
editor's quick fix and `wf fix --code T21` add an arm for every case the
`match` leaves out.
