    • Static Site Generation (SSG)

    Pre-render pages to HTML at build time for instant content visibility. JavaScript hydrates the page for interactivity.

    Enable SSG

    One config flag is all you need.

    { "build": { "ssg": true } }

    How It Works

    1. Build

    The compiler walks the AST for each page and generates static HTML from the component tree.

    2. Serve

    The browser loads pre-rendered HTML. Content is visible immediately — no blank white screen.

    3. Hydrate

    JavaScript runs and hydrates the page: attaches events, initializes state, fills dynamic content.

    Build Output

    SPA (default)

    build/ ├── index.html # Empty shell ├── app.js └── styles.css

    SSG mode

    build/ ├── index.html # Pre-rendered / ├── about/ │ └── index.html # Pre-rendered /about ├── blog/ │ └── index.html # Pre-rendered /blog ├── app.js └── styles.css

    What Gets Pre-Rendered

    Element SSG Behavior
    Static text, headings, components Fully rendered to HTML
    Container, Row, Column, Card, etc. Full HTML with classes
    Modifiers (primary, large, etc.) CSS classes applied
    Animation modifiers (fadeIn, etc.) Animation classes applied
    t() i18n calls Default locale text rendered
    State-dependent text Empty placeholder (filled by JS)
    if / for blocks Comment placeholder (filled by JS)
    show blocks Rendered but hidden (display:none)
    fetch blocks Loading block if present, else placeholder
    Event handlers Attached during hydration

    Dynamic Routes

    Pages with :param segments (e.g., /user/:id) cannot be pre-rendered — they fall back to client-side rendering.
