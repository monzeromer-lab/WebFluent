Concepts

Components

A component is a reusable element you declare: typed props, events, slots, parts and a body, checked like a built-in.

A component is a reusable element you declare yourself. It has typed props, the events it fires, the slots its caller fills, the parts it offers, and a body that draws it. The one thing to remember: the compiler checks a call to your component exactly as it checks a call to a built-in such as Button, so a missing prop or a misspelled flag is an error where you wrote it.

In this chapter

  • Declaring a component and calling it
  • Props, including enum props
  • Events, slots, scoped slots and parts

A first component

This page declares a Greeting component and places it once:

wf

component Greeting(_ name: String) { Text("Hello, {name}!") } page Home(path: "/", title: "Home", description: "A greeting.") { Heading("Welcome").h1 Greeting("Ada") }

The page shows the heading Welcome and the line Hello, Ada!.

  • component Greeting(…) declares the component. Its name is capitalised, as every element's is.
  • _ name: String is a prop. The _ lets a call pass it without its name, so Greeting("Ada") sets name to "Ada".
  • The block is the body: what the component draws each time it is placed.
  • Greeting("Ada") in the page is a call, written like any built-in.

Props

A prop is a value the caller hands to the component. This component takes four, with a type and, for three of them, a default:

wf

/// A person, at a glance. component UserCard(_ name: String, role: String, active: Bool = true, avatar: String? = null) { Card.elevated { Row(align: .center, gap: .md) { if let src = avatar { Avatar(src: src, alt: name) } else { Avatar(initials: name.slice(0, 2)).primary } Stack { Text(name).bold Text(role).muted } if active { Badge("Active").success } } } } page Team(path: "/") { UserCard("Monzer", role: "Developer") UserCard("Sam", role: "Designer", active: false, avatar: "/sam.png") UserCard("Ann", role: "PM").active }

The rules for props:

  • _ name: Type marks the one prop a call may pass positionally. It must be the first prop. Every other prop is passed by name.
  • Every prop has a written type: String, Number, Bool, Map, Any, [T] (a list), T? (may be null), or a declared type or enum. See Types for the whole type language.
  • = expr gives a prop a default, so a call may leave it out. A T? prop with no default defaults to null.
  • A Bool prop is set with a flag, .active, or by name, active: false.
  • A /// comment above the component or above a prop is its documentation. The editor shows it on hover, and wf docs prints it.

A prop that reads the caller's state stays live inside the component: a Chip(pressed: isOn) repaints when isOn changes. You do not need to pass a callback or re-render anything yourself.

The checker holds every call to the declaration. Leaving out a prop that has no default is C01; passing a prop the component does not declare is C02; a second positional argument is E113. A positional argument to a component whose first prop is not marked _ is bound to that first prop, with a C06 warning asking you to add the _.

Enum props

An enum prop takes one case of a declared enum. The caller picks the case with a flag or by name:

wf

enum Tone { calm, loud } component Note(_ text: String, tone: Tone = .calm) { Text(text) { style { padding: $sm; border-radius: $radius-sm } } } page Notes(path: "/") { Note("Quiet") Note("Loud!", tone: .loud) Note("Loud too").loud }

.loud and tone: .loud mean the same. A flag the enum does not have, such as .huge, is an error (E103) that lists the cases it does have.

The compiler writes a component's enum props to its root element as data-<prop>="<case>" — here data-tone="loud" — so a stylesheet can select on them: .note[data-tone="loud"] { font-weight: 700 }. See Styling for project stylesheets.

Events

An event is how a component tells its caller that something happened. The component declares it with event name(param: Type) and fires it with emit name(value). The caller handles it with on name(value) { }, as it handles a click:

wf

type Todo { id: String, title: String, done: Bool = false } component TodoRow(_ todo: Todo) { event toggle(id: String) event remove(id: String) Row(align: .center, gap: .sm) { Checkbox(checked: todo.done, label: todo.title) { on change { emit toggle(todo.id) } } IconButton(icon: "trash", label: "Remove {todo.title}").sm { on click { emit remove(todo.id) } } } } page Todos(path: "/") { state todos: [Todo] = [Todo(id: "1", title: "Milk"), Todo(id: "2", title: "Eggs")] action toggle(id: String) { todos = todos.map(todo => if todo.id == id { Todo(id: todo.id, title: todo.title, done: !todo.done) } else { todo }) } for todo in todos by todo.id { TodoRow(todo) { on toggle(id) { toggle(id) } on remove(id) { todos = todos.filter(todo => todo.id != id) } } } }

The checker holds each emit to the parameters its event declares (T09). A handler on a call must name a declared event or a DOM event; an emit outside a component is E114. A DOM event handler written on a component call, such as on click, attaches to the component's root element (see What a call puts on the root element). For events in general, see Events.

An event with several values

An event may send several values. The handler names them in the order the event declares them, and each name has the type declared for it. In this example key is a String, and x and y are Numbers:

wf

component Entry(_ key: String) { event menu(key: String, x: Number, y: Number) Button(key) { on contextmenu(e) { e.preventDefault() emit menu(key, e.clientX, e.clientY) } } } page Files(path: "/") { state at = "nothing yet" Entry("notes.wf") { on menu(key, x, y) { at = "{key} at {x}, {y}" } } Text("Menu for {at}") }

A handler may name fewer values than the event sends: on menu(key) reads the key and ignores the rest. It may not name more. A name past the last value would always be undefined, so the checker reports it (T22). You handle an event that sends nothing with no names: on close { }.

Slots

A slot is a place in the component where the caller's content goes. The component places the caller's block with children, and may declare named slots that the caller fills with name { … }:

wf

component Panel(_ title: String) { slot slot trailing Card { Row(justify: .between, align: .center) { Heading(title).h3 trailing } children } } page Keys(path: "/") { Panel("API keys") { trailing { Badge("Beta").info } Text("Rotate every 90 days.") Button("Generate").primary } }
  • slot declares the default slot, which the body places as children.
  • slot trailing declares a named slot, which the body places by its name.
  • Anything in the call's block that is not a named fill goes to the default slot. Here that is the Text and the Button.

A fill is compiled in the caller's scope: it reads the caller's state and loop variables, and its handlers are the caller's. The component only decides where the fill lands. A page's layout: is a component with a default slot, called with the page as its block (see Pages and routing).

Scoped slots

A scoped slot hands values to its fill. The component declares what it hands over, places the slot with those values by name, and the caller's fill names them in order:

wf

type Todo { id: String, title: String, done: Bool = false } component TodoList(items: [Todo]) { slot row(item: Todo, index: Number) slot empty if items.length == 0 { empty } else { for it, i in items by it.id { row(item: it, index: i) } } } page Use(path: "/") { state todos: [Todo] = [Todo(id: "1", title: "Milk")] TodoList(items: todos) { row(todo, i) { Text("{i + 1}. {todo.title}") } empty { Text("Nothing to do.").muted } } }

The page shows 1. Milk. The fill's names take their types from the slot declaration: todo is a Todo and i a Number. The fill is drawn again when a value it is handed changes.

Parts

A part is a component of the component's own, called under its name — the way Card.Header is a part of Card:

wf

component Panel(_ title: String) { part Header(_ text: String) { Heading(text).h3 } part Footer { Divider Text("End").muted.sm } Card { Text(title) children } slot } page Parts(path: "/") { Panel("Keys") { Panel.Header("Rotate") Text("Body") Panel.Footer } }

You declare a part inside its component. A part has props, events and slots of its own, but it cannot declare parts: a part inside a part is an error. Calling a part outside its owner, such as Panel.Header with no Panel around it, is C03.

Local state and actions

A component may have its own state, derived values, effects, actions, timers and handles. Each placed instance gets its own copy, so two Steppers count separately:

wf

component Stepper(_ start: Number, step: Number = 1) { event change(value: Number) state n = start derived even = n % 2 == 0 action move(delta: Number) { n = n + delta emit change(n) } Row(gap: .sm, align: .center) { Button("−").sm { on click { move(-step) } } Text("{n}").bold Button("+").sm { on click { move(step) } } if even { Badge("even").info } } }

What an instance creates — effects, timers, listeners — is disposed of when the instance leaves the page. See State and reactivity for state, derived and effect.

Stores inside a component

use StoreName brings a store into a component, as it does into a page. Every instance reads and writes the same store:

wf

store Cart { state items: [String] = [] action add(name: String) { items.push(name) } } component AddToCart(_ name: String) { use Cart Button("Add {name}").primary { on click { Cart.add(name) } } } page Shop(path: "/") { use Cart AddToCart("Pen") Text("{Cart.items.length} in cart") }

Clicking Add Pen changes the page's text from 0 in cart to 1 in cart. Stores covers stores in full.

What a call puts on the root element

A component's root element is the one element its body draws at the top. Some of what you write on a call goes to that element rather than to a prop:

  • A DOM event handler: Chip("x") { on click { … } } attaches to the root, so a styled button component is clickable wherever you place it.
  • class:, which is added to the root's own classes.
  • A style { } block, which styles the root: Tile(label: "a") { style { grid-column: 2 / span 2 } } places that tile in its grid. Its rule's class joins the root's classes, as class: does.
  • An attribute the component takes no prop for: aria-*, data-*, id, role, title and hidden. You write it as you would on an element: data-open: true is data-open="true", and false writes no attribute, except for an ARIA state, which keeps "false".
  • mount:, update: and cleanup: (see JavaScript interop).
  • drag:, the drop…: props, on receive, on dragmove, on longpress and on swipe. These need one root element: on a component whose body is an if, a for or several elements they are C07.

When the component declares a prop of that name, it receives the value instead and decides where it goes. Declare the prop when the root is not the right element for it. This Chip takes the class and the description as props and puts them on its Badge:

wf

component Chip(_ label: String, extra: String = "", note: String = "") { Badge(label, class: extra, aria-description: note) } page Chips(path: "/", title: "Chips", description: "Styled by the caller.") { Heading("Chips").h1 Chip("Beta", extra: "chip-beta", note: "Not finished yet") { on click { log("beta") } } }

The on click still goes to the root, which here is the Badge.

Designing components

A component's interface is its props, events, slots and parts. These guidelines keep it clear to callers.

A value down, an event up

A component does not take bind:. To make a control of your own, take the value as a prop and fire an event when it should change. The caller decides what to do with the new value:

wf

component Stepper(_ value: Number, label: String, min: Number = 0) { event change(value: Number) Row(gap: .sm, align: .center) { Button("−", disabled: value <= min).sm { on click { emit change(value - 1) } } Text("{label}: {value}") Button("+").sm { on click { emit change(value + 1) } } } } page Booking(path: "/", title: "Booking", description: "How many seats.") { state seats = 1 Heading("Book").h1 Stepper(seats, label: "Seats", min: 1) { on change(v) { seats = v } } }

Clicking + sets seats to 2, and the component shows Seats: 2 because its value prop reads seats.

Pick the right way in

Choose the part of the interface by what the caller wants to do:

Pick the right way in
The caller wants to… Use
configure it with a value a prop
choose one of a few looks

an enum prop, set with a flag
put any content inside

the default slot, children
put content in a particular place a named slot
render each item its own way

a scoped slot, slot row(item: T)
offer a sub-element with its own props

a part, Panel.Header
hear that something happened

an event

Keep state where it is read

A component's own state is right for what only that component cares about, such as whether its menu is open or it is hovered. What the page or other components care about comes in as a prop and goes out as an event — or lives in a store.

Document it

A /// comment above the component, a prop or an event is shown on hover in the editor and in the gallery wf docs writes.

Other people's code

To use a JavaScript library — a chart, a map, an editor — call it from a .js file under src/ and hand it an element with mount: and cleanup:. To place somebody else's custom element, use Element("tag-name", …). You can also publish your components as custom elements for another framework to place. All three are in JavaScript interop.

Components in the pre-rendered page

A static build pre-renders each page to HTML — the static paint. It expands every component call into HTML at build time: props substituted, slots filled, and loops and branches over the seeded state drawn. A page built from components is therefore a complete page before any script runs. See Static sites and SPAs.
