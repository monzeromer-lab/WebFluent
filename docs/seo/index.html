Search & Sharing

Everything a search engine reads and a chat app previews, generated from the page you already wrote.

One setting turns it on

Add your site's own address. The compiler knows every route, so it can write the rest itself.

{ "meta": { "site_url": "https://example.com", "site_name": "Ledger", "description": "Used by any page that sets none", "image": "/card.png" } }
Without site_url, the tags that need an absolute address are left out rather than guessed at. A canonical pointing at the wrong host is worse than no canonical at all.

Describing a page

Four optional attributes on any page. Everything else is derived.

Page Post (path: "/blog/slow-roasting", title: "Slow roasting, explained", description: "Why we take eleven minutes over it.", type: "article", image: "/roast.png") { Container { ... } }
Attribute What it does
title The tab title, the search-result heading and the card headline
description The snippet under a search result, and the preview text in a shared link. Around 160 characters before it is cut.
image The preview image. Site-relative or absolute; either way it is made absolute in the output.
type "website" by default, or "article" for a post — which also changes the structured data type.
noindex A bare flag. Keeps the page out of search results and out of the sitemap.
Page Draft (path: "/draft", title: "Draft", noindex) { ... }

What each page gets

Written into every page's head, with no further configuration.

A canonical URL

Absolute, and pointing at itself. This is what stops two addresses for one page competing with each other in the rankings.

<link rel="canonical" href="https://example.com/blog/slow-roasting">

A sharing card

Open Graph and Twitter tags, so a link pasted into a chat unfurls with the right title, text and picture.

<meta property="og:title" ...> <meta property="og:description" ...> <meta property="og:image" ...> <meta name="twitter:card" content="summary_large_image">

Structured data

JSON-LD describing the site, the organisation, the page, and a breadcrumb trail built from the route itself.

{"@type":"Article", ... } {"@type":"BreadcrumbList", ... }

Language alternates

When i18n declares more than one locale, every page lists each variant and itself, plus an x-default fallback.

<link rel="alternate" hreflang="en" ...> <link rel="alternate" hreflang="ar" ...> <link rel="alternate" hreflang="x-default" ...>

Sitemap and robots

Written to your build directory alongside the pages. The compiler already knows every route, so there is nothing to keep in step by hand.

build/ sitemap.xml robots.txt

Dynamic routes, catch-alls and noindex pages are left out. Neither priority nor changefreq is emitted, because Google ignores both — writing them implies a control you do not have.

Turn the pair off with:

{ "meta": { "sitemap": false } }

What the compiler tells you

Four warnings, none of which fails a build.

Rule Meaning
S01 A page with no title — nothing to show as the result link
S02 A page with no description, so its snippet gets written for it
S03 A description a search result will cut mid-sentence
S04 Two pages claiming the same route

Static builds rank better

A crawler that runs no JavaScript sees only what is in the HTML. With SSG on, that is the whole page — including lists built from seeded data, which the compiler resolves at build time rather than leaving to the browser.
