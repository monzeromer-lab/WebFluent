About

Essays on why WebFluent works as it does: read once, for the argument, not looked up.

Why WebFluent

Why the language exists, and the choices it makes: one meaning per word, a compiler that refuses what would break in the browser, and one source for the web and for paper.

How reactivity works

What happens between a click and the one text node it changes: signals, derived values, effects, branches and keyed lists, with no virtual DOM in between.

Accessibility

Build pages that work with a keyboard, a screen reader or voice control: what the built-ins do, what the compiler checks, and what is still yours to do.

Security

What the compiler guarantees, what it cannot, and the decisions left to you: markup, secrets, storage, headers and a deployment checklist.

What a build ships

Learn what a build already does to be fast, see what it weighs, set budgets that warn, time pages in a browser, and avoid what makes a site slow.

Static or single-page

The same source builds as pre-rendered pages or as one app shell. What each gives you, what the pre-rendered page holds, and how dynamic routes are rendered.

Upgrading

What changed in each release, what to do when you upgrade, and how wf migrate carries an older project forward.

Contributing

How the compiler is put together, how to build and test it, and how to change the language, a built-in or this guide.
