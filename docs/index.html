One language for the web, and the page it prints to.

WebFluent is a typed language that compiles to a static site, a single-page app, a PDF or a slide deck. It is one binary: no Node, no bundler, no config — and a compiler that finds your mistakes before a browser does.

Quick start

A running site in three commands

Install wf, create a project from a template, and start the dev server. There is nothing else to install and nothing to configure first.

Getting started, step by step →

bash

$ wf init hello -t static $ cd hello $ wf serve Starting dev server at http://localhost:3000/
  1. wf init writes a small, working project — pages, components, a store and tests — so you start from something real.
  2. wf serve builds it and serves it. Open http://localhost:3000.
  3. Edit src/pages/Home.wf and save: the page rebuilds and reloads. A mistake shows over the page, with its fix, until you save again.

Checked as you write

Mistakes are errors, not blank pages

Every element, prop, flag, record field and store member has a declared shape, and the compiler holds your program to it. A typo is caught where you wrote it, with the fix — not discovered later as something missing in the browser.

How it works

Five ideas, and the rest follows

01

A file is declarations

Thirteen kinds — page, component, store, theme, app, type, enum, api, const, data, image, animation and test. Each page names its own route; there is no route table to keep in sync.

Learn more

02

An element is a typed call

One positional value, named props, flags after a dot, then a block. The compiler knows what every built-in and every component of yours accepts.

Button("Save").primary.lg { on click { save() } } Learn more

03

State is a signal

state count = 0, and whatever reads it follows it. Derived values recompute and only the text or attribute that changed updates. No dependency arrays.

Learn more

04

Styles are CSS, beside the element

A style { } block is real CSS — values, $tokens from your theme, &:hover and media queries — compiled to one stylesheet with only what you used.

Learn more

05

The build is the whole site

wf build writes pre-rendered HTML for each page, a runtime cut to what you use, a sitemap, link previews and a content-security policy the build checks itself against.

Learn more

Coming from React, Vue or Svelte?

Start from what you know: state is a signal, components are declared and typed, stores replace context, and resource replaces your data-fetching library.

What a real site needs, already in the language

A service, described once

api Backend { get users() -> [User] } — every call typed, cached, retried and cancellable. Or read the whole service from an OpenAPI file.

Read the guide

Forms that validate themselves

validate email { required email } beside the state. The field shows its message accessibly, and a failed submit moves focus to the problem.

Read the guide

Sockets, streams and peers

WebSockets that reconnect, server-sent events, a channel every tab hears and WebRTC to another reader's page — each closed when its page leaves.

Read the guide

Works offline

Name offline in the config: a service worker stores the site, writes wait for the connection, and a new version is offered, never forced.

Read the guide

Every language, both directions

One JSON file per locale and t("key") to read it. Plurals follow each language's rules, and Arabic or Hebrew flips the page right to left.

Read the guide

Tests that click

click "Save" then expect "Saved" runs in a real browser, and wf verify loads every page of the build and fails on any error.

Read the guide

Safe by construction

Text is always text, there are no inline handlers or javascript: links, private env values stay out of the bundle, and the build holds itself to a strict CSP.

Read the guide

Your JavaScript, by name

A plain .js file under src/ is linked as written, and its functions are called straight from .wf, checked against their JSDoc.

Read the guide

Outputs

One source, four things to ship

build.output_type in webfluent.app.json chooses what wf build writes. The PDF and slides come from the compiler's own layout engine — no headless browser.

Static site

"static"

One pre-rendered HTML file per route that works before any script loads, then hydrates in place. The right default for anything people search for.

Single-page app

"spa"

One shell and a router that draws pages in the browser, each page's code fetched the first time its route shows.

PDF document

"pdf"

Invoices, reports and résumés, laid out with the same CSS as the web: headers, footers, page breaks, charts and Arabic text.

Slide deck

"slides"

A Presentation of Slides written like any other page, one slide per PDF page — generated from your data if you like.
