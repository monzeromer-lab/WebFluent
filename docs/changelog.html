6.0.0

#6.0.0

Latest

13 November 2026

A page can be in a language of its own, the compiler holds up to anything it is given, and the Rust library has a smaller surface with typed errors. A project that builds with 5.14 builds with 6.0, unless it relied on something now refused because it shipped a broken page (a status code the grammar cannot hold, nesting past 100 levels). What 6.0 breaks on purpose is the Rust API (see "Upgrading").

Additions

4

  • lang: on a page. page HomeEn(path: "/en", lang: "en", …) is written <html lang="en"> (and dir="rtl" for a language written right to left), with its own og:locale and inLanguage on its JSON-LD WebPage. The router sets lang and dir on <html> when it shows the page, and puts back the site's language, or the locale the reader chose, on a page without one. wf render uses it when no --lang is given. A site whose pages declared one language each used to ship every page in meta.lang, so crawlers and link previews read its English pages as Arabic (#6).

  • translates: on a page. translates: Home names the page this one is a translation of. Pages joined this way, directly or through each other, list each other as hreflang alternates, each at its own address, canonical to itself and in its own lang:, with x-default for the one in the site's language, and name each other's languages as og:locale:alternate. A :param page's translation is matched by its parameters (/en/posts/:slug for /posts/:slug).

  • R05: a translates: that names no page or its own, or two translations of one page in one language.

  • worker is offered where a statement starts, beside socket, stream, channel and peer.

Faster

3

Measured on the documentation site (77 files, 140 pages); cargo xtask bench reproduces the numbers.

  • wf build takes 0.36 s instead of 4.4 s, to the same bytes:

    • pages are painted, compressed and read back on every core;

    • a data constant is shared rather than copied each time a page reads it;

    • the compressor finds its matches faster, and is run once a file rather than twice;

    • wf allocates with mimalloc.

  • wf check takes 62 ms instead of 82.

  • The language server answers in about 0.1 ms instead of 46:

    • it keeps the analysed project between requests, and analyses it again only after a change;

    • an unchanged file keeps its parse and its tokens.

    An edit's findings arrive in 74 ms instead of 145. Before, a hover cost as much as checking the whole project and grew with it.

Fixes

15

  • No more ?lang= alternates. A project with several i18n.locales listed ?lang=<code> for each as an hreflang alternate, but every ?lang= address serves the default locale's HTML with the bare address as its canonical, so a search engine filed each one as a duplicate and ignored the set (#5). A locale the browser switches to on one address is not an alternate; translations with translates: are. ?lang= still opens a page in that locale for a reader who follows such a link.

  • The compiler cannot be made to hang or crash by what it reads. A name starting with a letter such as ℘ no longer loops forever; nesting past 100 levels is E120 instead of a stack overflow; a template render is bounded (E121); the parser and the PDF engine return an error for input they cannot read rather than panicking; a picture is refused past 50 megapixels before it is decoded.

  • Names in any script repaint. A state named in Arabic (state عدد) is reactive in the bundle, and a name may start with any letter Unicode allows in an identifier.

  • Text is written as text. A \ or ${ in a spliced string, a page title, a class or a colour from data, a head { } tag and a Frame are escaped where they are written, and the build reads its own pages back as a browser would before it ships them. A template's data cannot add CSS declarations or attributes.

  • Template answers as wf build does: one evaluator and one renderer serve both, so name.length, comparisons and indexing agree.

  • A page's state no longer leaks into app, and a rendering server that catches a panic no longer carries one render's state into the next.

  • Every parse error is reported, not only the first; findings are in a fixed order and placed by character, not byte.

  • Numbers the grammar cannot hold are refused (a status past 599, a fractional one, a negative carousel interval) instead of being clamped.

  • .wfx lexing is linear in the size of the file.

  • Runtime: a disposed effect lets go of what it read; carousels, drawers, popups, now, VirtualList and submenus go with their page; navigate() and the router stay on the site; the request engine and the connections are bounded, and credentials never enter the offline queue; the service worker keeps sites under one origin apart.

  • Builds stay in their project. build.output outside the project is refused unless --allow-output-outside says so, wf serve listens on this machine unless --host says otherwise and serves nothing outside the build, and a public_env name takes no value from the shell unless WF_ALLOW_SHELL_ENV names it.

  • wf verify and wf test run Chrome with its sandbox, in a private profile that goes when wf does.

  • I/O errors name their file, and a config or translation that is there but cannot be read is an error rather than the defaults.

  • SVG text is laid out with the document's own fonts.

  • wf check --allow-output-outside, as wf build has: a project whose build.output is outside it could not be checked at all.

Editors

7

  • The grammars read names in any script, raw strings of any length and two declarations on one style line as the compiler does.

  • Zed colours worker and expect not, outlines parts and persisted state, and has snippets for persist, validate, on key, api and test.

  • VS Code colours every style property, colour and regex literals, a splice's format, /// and // wf-allow(…), and the indented layout's blocks.

  • The language server reads the compiler's own tables for keywords, events, built-in names and design tokens, and follows a component's props, events and slots for definitions and renames.

  • Both extensions download the release they pin and check it against SHA256SUMS.

  • VS Code colours a name in any script as the compiler reads one, and tells a member (e.message) from a flag (.danger).

  • The grammars read a raw string inside code that does not parse yet.

For tools (the Rust library)

8

  • One documented surface. template, syntax (the AST, fmt, layout), diagnostics, build, config, vfs, outfs, memory, init, studio and the root items are the API semver covers.

  • The rest is the crate's own: the checker, the code generator, the PDF engine, the registry and the tools. The internals feature makes them public again, hidden from the docs and outside semver, for a tool that accepts that they change in any release.

  • One path per item. The root's second paths (webfluent::lexer, ::parser, ::fmt, ::error, ::assets, …) are gone; use the layer's (webfluent::syntax::fmt, webfluent::diagnostics::error).

  • One finding type. The linters and the studio return diagnostics::Diagnostic; A11yWarning, VocabWarning and studio::StudioDiagnostic are gone (rule_id is code).

  • Typed errors. WebFluentError::IoError, ConfigError, CodegenError, EditError and NotFound hold their own types, each a message and the error beneath it, which source() walks. Build one with WebFluentError::io(…), or io_with(message, cause) to keep the cause; ? on an io::Error keeps it too. What an error prints is unchanged.

  • #[non_exhaustive] on WebFluentError, the AST's enums that gain cases (Declaration, Expr, StatementKind, TypeRef, Step, …), Plan, Tag, OutputType, RuntimeMode, ScriptLoad, init::Template, memory::Contents, EditOp and ArgRef.

  • Dependencies are up to date: every crate at its newest release the crate's Rust version accepts, taffy 0.15 and miniz_oxide 0.9 among them. usvg 0.47 and fontdb 0.23 stay where krilla-svg holds them.

  • Every public Result says when it fails; builders are #[must_use]; the lexer, parser and code generator implement Debug; a choice that was two bools is an enum.

Upgrading

3

  • A project: nothing to change. A multilingual site that relied on the ?lang= alternates had them ignored by search engines already; to have each language indexed, give it pages of its own with lang: and translates:.

  • A program using the crate:

    • a path that no longer resolves moved to its layer (webfluent::fmt → webfluent::syntax::fmt);

    • a module that is no longer public (webfluent::sema, codegen, paged, registry, platform, …) needs features = ["internals"], and pins an exact version, since those change in any release;

    • a match on an enum above needs a _ arm;

    • WebFluentError::IoError(msg) as a value is WebFluentError::io(msg); as a pattern, IoError(e) binds the error, whose message() is the old string.

  • The editors pin this release: update the extension after it is out.

5.14.0

#5.14.0

12 November 2026

The compiler runs in a browser. Built for WebAssembly, it does in a page what wf build does on a machine — sites and apps, every check, pictures sized to WebP, PDFs and slide decks — with nothing sent to a server. It is what the documentation's playground runs.

Additions

4

  • The compiler as WebAssembly (crates/wf-wasm). wf.js is the one thing a page imports: compile(files, config) takes a project as a map of path to text or bytes and gives back the files the build wrote, its pictures and PDFs, and every finding exactly as wf check --format json lists them; check, explain and registerFont beside it. A demo page compiles as you type.

  • Loaded by what a project needs. The compiler is about 1.6 MB gzipped, fetched on the first call. A project whose config asks for a PDF or a deck loads a second build with the paged engine (about 2.7 MB) and the fonts it is set in, then and only then; a face for Arabic is fetched the first time a document has Arabic in it, since a browser has no machine fonts to fall back on.

  • A preview served as a host would serve it. preview(out) hands a build to a service worker that answers for it under preview/ — every page, chunk, stylesheet and picture, and the routes between them.

  • Pictures in the browser. libwebp is compiled to WebAssembly against a C library of its own, so a picture is sized and written as WebP as wf build does it; the encodings are kept from one build to the next, so an edit that leaves the picture alone does not encode it again.

For tools

5

  • webfluent::memory: compile and compile_files build a project from memory — no disk read, none written — with the findings and the output as values. It runs natively as well.

  • webfluent::outfs is where a build writes: the disk, or memory inside outfs::capture. webfluent::platform stands in for threads, clocks and the environment where WebAssembly has none.

  • OverlayVfs::set_bytes lays a file that is not text (a picture, a font) over a path.

  • The paged engine reads a project's fonts and pictures through the Vfs it is given (Options::from_pdf_via, from_slides_via, reader_via), and paged::fonts::register_font takes a face — a font file as it is, zlib or gzip — that stands where a built-in one does.

  • Three features for a WebAssembly build: webp, pdf and bundled-fonts. A native build has all three whatever the features say, so default-features = false leaves PDFs and WebP as they were.

Fixes

5

  • A style { } on a component's call styles the component. Its rule was compiled and its class put on nothing, so placing a component in a grid or sizing it from its call did nothing. The class now joins the root's classes, as class: does, on the live page and in the static paint.

  • An if let value whose branch awaits compiles. if let p = x { await f(p) } else { … } used as a value made a plain arrow with an await in it, and the page's code did not parse; it is now an async arrow, awaited.

  • D01 reads public/ through the project's Vfs, as every other check does, so an editor's unsaved picture or a project held in memory counts as there.

  • An @font-face in a PDF is read from its bytes, not written to a temporary file first.

  • The agents' skill says which compiler it is for. just bump now sets the skill's version and its copy of AGENTS.md with the crates, and the release preflight refuses a skill left behind. 5.13.0 shipped saying 5.12.0.

Upgrading

Nothing to change. A project builds to the same bytes as it did with 5.13.0.

5.13.0

#5.13.0

11 November 2026

WebFluent for coding agents: a skill that teaches the wf loop, a reference with a part written for agents, and a core an agent is given whole. An editor's preview follows a style or text edit with no reload. And a run of fixes to what a running page reads while a change is still going on.

Additions

6

  • A writing-webfluent skill for coding agents. Agents that read Agent Skills (Claude Code, Codex, Gemini CLI, Copilot, Zed and others) can install one skill that teaches the loop: ask the compiler what a component, store or token is before writing, then check, explain, fix, format, test and verify. It names the mistakes models make most, each with its code. References an agent reads by task go with it: code quality and a review checklist; recipes (one small app in fifteen pieces); styling (the tokens, themes, right to left); testing; diagnostics (each common code, its cause and fix); PDFs, decks and server rendering; and apps with Tauri for the desktop and the phone (the typed bridge script, capabilities by platform, safe areas, Android's back gesture, signing). A test compiles every example in them with no warning, and checks that every command and code they name is one wf has. The README says how to install it.

  • wf init gives every new project the skill, in .agents/skills/ and .claude/skills/; its language reference points at the project's AGENTS.md rather than repeating it.

  • The reference has a part for agents. AGENTS.md gains "For agents": the grammar in a few lines, ten idioms, the mistakes made most (T06, C02, X05, T13, E002, T17) and one whole page; every example compiles with no warning.

  • AGENTS.md covers Tauri and Electron apps, on the desktop and the phone.

  • Eleven icons for a design tool: pointer, reach, frame, line, pipette, comment, hand, zoom, ruler, eye-off and unlock.

  • PDFs and decks draw the logical insets (inset-inline, inset-block), read left to right as the logical paddings already were.

For tools

7

  • webfluent::patch: in_place compares two programs and answers with what a running page must change to follow a style or text edit (one class swapped and its rules, or an element's new text), or a rebuild and why. in_place_with takes the project's breakpoints, and agrees holds a patch to what a full build generates.

  • webfluent::agent::context::reference_core() gives the sections of the reference an agent needs first, under 8,000 tokens; reference_section(title) gives any other.

  • Style values: the logical pairs (padding-inline, margin-block, inset-inline, …) are a Pair shape, and grid-column/grid-row a Placement, each printed in the fewest words and edited one side or line at a time; cell, read_placement and edit_placement are what a drop in a grid writes.

  • A token set by theme.tokens carries that value, so an editor can say the config overrides the theme's own. A theme's view can be of a theme the project declares other than the one the config selects.

  • An agent's prompt prints the config with its keys sorted at every depth, so one project always reads the same and keeps the prompt cache.

  • ChangeSet is Clone, and absorb_reads takes back what a copy read.

  • An editor's preview is no longer compressed, which took most of a warm build's time.

Fixes

7

  • A cached request that fails no longer leaks an unhandled rejection. A resource with cache: whose request failed reported an uncaught error beside the failure its error arm handled.

  • A derived value read while a change is running is up to date. An action an effect called, which wrote a state and then read a derived value of it, got the value from before its write.

  • A change runs its effects oldest first, so a branch that leaves disposes of what it drew before any of it reads again; before, an attribute could throw on the null and keep the branch from leaving. One effect that throws no longer keeps the others from running.

  • A store's derived values are worked out with the other stores in reach, in a test's render and a page rendered at build time, where a derived value reading another store came out empty.

  • mod+shift+/ matches. With Shift, a punctuation key sends its other character, and keyIs refused it; it is now read by its place.

  • A locale whose file is not JSON says why, with the line and column, instead of reading as a file with no messages.

  • The reference says what the compiler does. Every example in AGENTS.md compiles: the Row, Grid and Stack rows wrote gap: md (T13), key rule 20 wrote a deck in WebFluent 2 syntax, and others bound query, named a loop t, used tokens no theme declares or bound a DatePicker to a string. It counts 83 icons (it said 32 and 72, as did the guide), gives the runtime's current sizes (2 of 41 modules, 6.8 kB gzipped for a static page), lists E119, V12 and I05 as the warnings they are, adds rows for E005 and T22, and documents wf render, six CLI flags, theme.dark, theme.builtin: "structural" and i18n.literals. wf init writes this reference into a new project, so only a wf of this release gives a project the corrected one.

Upgrading

Nothing to change: run wf check.

5.12.0

#5.12.0

3 November 2026

A project written in Arabic, and translated by its own words: names in any script, every string a reader sees looked up by the text as written, plural forms chosen by the number in the text, and a locale that names its digits. Every name a program binds is now its own, whatever the generated code or the browser calls its own things. And the guide is rewritten, chapter by chapter, by what a reader is there to do.

Additions

11

  • Translate a project by its own words (chapter 28). With "literals": true in i18n, every string a reader sees (an element's text, its label:, title:, placeholder:, aria-label: and alt:, a record's text field, a value whose name says it is words, such as caretText or emptyLabel) is looked up in the locale's table by the text as written, and the source stays in the language it was written in. A string that splices a value is one key, with a placeholder named after it; Markdown written in place and a control's labels: are words too. wf test translates the program as the build does. What no table can translate (a text splicing more than a name) is the new warning I05, where it is shown.

  • Plural forms by the number in the text (chapter 28). A message with plural forms and exactly one number among its values takes its form by that number, so Text("{files} files") reads right in Arabic's two, few and many. With two numbers none is guessed.

  • A locale may name its digits (chapter 28). setLocale("ar-u-nu-arab") reads the ar table and writes format, ago and every count in Arabic-Indic digits; ar-u-nu-latn is 0–9 whatever the browser would pick. A date pattern's figures follow, and a is AM or PM in the locale's words. The document's lang stays the language, so a stylesheet's [lang="ar"] still matches.

  • t() in a store, and setLocale() with it, where both compiled to calls the page could not find.

  • Names in any script (chapter 9). A program's own names start and go on as Unicode's UAX #31 says, with the marks of their letters, and are one name however they were typed: state عددٌ = 3, store المهام, action أضف. The editor grammar reads them the same way. A bidirectional embedding, override or isolate control in the source, which draws code one way while it runs another, is the new warning E119.

  • Markdown draws GFM tables (chapter 27), the same at build time and in the browser: a header row, a delimiter row whose colons align each column, and \| for a pipe inside a cell.

  • Frame(srcdoc: html, sandbox: "") (chapter 21) is a declared prop, where it was an attribute passed through with a C04 warning. A value that reads state is followed, so the frame redraws as it changes.

  • A picture may carry itself: a data:image/… address on an Image's or an Avatar's src:, a Markdown picture or a sanitized <img> is kept, in the live page, the pre-render and the template engine alike. A link, a frame, a form, and any data: that is not an image, are still refused.

  • Fourteen icons (chapter 21), 72 in all: code, monitor, git-commit, play, layers, insert, grid, list, square, pill, image, sparkle, lock and type. An icon drawn in the browser now carries data-icon, as a pre-rendered one did, so a style keyed on the name matches both.

  • WebP is lossy at build.media.quality (chapter 42), through libwebp, keeping alpha: a 23 kB PNG that came out as 189 kB of WebP is now 5 kB. A file that would be no smaller than its original is not written, and wf assets --plan says which widths were dropped.

  • output_type: "static" pre-renders every page, as ssg: true does. The config accepted it and built a single-page app.

For tools

7

Each is for a tool built on the compiler (chapter 41); paths are under webfluent::.

  • agent::edit replaces each old_text where it is found exactly once: exactly, then ignoring line endings, then the indent, then with typographic quotes and dashes read as ASCII. Text found twice names its lines, text found nowhere the three nearest, and the edits apply all or none. ChangeSet::edit makes them on a file the set has read, and refuses one that moved since; a missing file is WebFluentError::NotFound. ChangeSet::edited shows what the edits would make of a file, before and after, without changing the set, and ChangeSet::dir names the project's folder.

  • A change set over newer buffers: it can be laid over buffers that moved on, keeping what it wrote and read, and hands back a file's text without its own change, for writing the hunks a reader accepted. It never reaches outside the project through a link.

  • Editing a style block's nested rules: SetRuleStyle and RemoveRuleStyle reach an @media or &:state rule, making it when there is none. SetStyle and AppendChild keep the block as it is written, and SetProp on Card.elevated writes the prop before the flags, where it wrote a call that did not parse.

  • Template::with_studio writes each element's node id on what it draws (data-wf-node, data-wf-call), as the builds do for an editor.

  • A preview's resources held in an arm: data-wf-resource="loading" or "error" on a page's root makes every resource read as in that arm.

  • contrast::ratio is public, and a theme's view names as unpaired every colour token the dark theme leaves alone, not only color-*.

  • wf commands --json reads each value's kind in a release build, where it said every path was text.

Fixes

19

  • A program's names are its own wherever it binds them. A loop's item, a lambda's parameter, a let, a caught error, an action, a const, a store or a service named like the generated code's own things (_p, e, event, document) or a browser global (Map, Set, Node, setTimeout) used to read the wrong value or stop the page from drawing: for e in entries { Link(to: "/e/{e.id}") } went to /e/undefined, and const Map = 3 threw before any page drew. Each is now spelt apart in the generated code, and the build's read-back of its own JavaScript (E901) catches a clash that slips past.

  • A store member named like what every object has (valueOf, toString, constructor) is E118, where the page threw as it drew; such a name now works as a prop, and __proto__ as a prop is E118.

  • A component call's handlers and attributes follow its root when the body's if or match draws a new one: a button wrapped in a tooltip while disabled kept its click once enabled.

  • A state may start from a derived value defined before it, where it threw as the page drew.

  • A derived function works everywhere: the pre-render, wf test and wf render painted every call to derived countOf = (id) => … blank, inside a lambda too.

  • A select keeps its value when its options are redrawn.

  • A modal reopened before its close event arrives stays open.

  • A drag whose first move leaves its element still begins, in WebKit too, and a draggable element selects no text.

  • A shortcut on a punctuation key is found by its place on a layout that types no ASCII there, so mod+, works on an Arabic keyboard.

  • A name narrowed out of null may still be set to null.

  • A member or field that does not exist is reported at its name (T06 underlines x, not the store), so the build and the editor agree.

  • V01 offers the dot for a flag written without it (Button(primary)), and no longer matches a two-letter word to any short name.

  • F04 no longer warns about a checkbox that is always disabled.

  • A binding that runs again with its value writes nothing, the browser asks about reduced motion once, and a windowed list fed an item at a time lays out once a frame, revealing after it is laid out.

  • A test's settle waits as long as it asks, not two seconds each, and an expect reads a page still moving again until it holds, for up to a second and a half. A file of fifteen browser tests went from two minutes to eighteen seconds.

  • A test file's declaration named like one of the project's is E102 where the tests are collected, where every browser test failed with a SyntaxError.

  • A prop that reads a store named like a browser global is followed, not copied once.

  • A fix's word search no longer panics on a character it would end inside.

  • Chart and QrCode are in the Data display group, so a list of the registry by group draws it once.

The guide

Every chapter is rewritten to a house style drawn from a study of developer documentation, and the chapters are ordered by what a reader is there to do: start, learn the language, build the parts of an app, ship, and look things up. The site has a front page that answers a visitor's questions in order, and its pages, sidebar and search come from the guide.

Upgrading

See chapter 51: store members named like an object's own (E118), a test declaration named like the project's (E102), where T06 is reported, output_type: "static", and smaller WebP. Run wf check.

5.11.0

#5.11.0

29 October 2026

What an editor written in WebFluent asked of the language: a handler that reads every value an event sends, gestures on a component's call, a modal's own heading and close button, source maps, a translated wf init, and icons; and tests that find a control by the name a reader hears, each test file with its own declarations.

Additions

6

  • A handler names each value its event sends (chapter 9). A component that declares event menu(key: String, x: Number, y: Number) and emit menu(k, x, y) is handled with on menu(key, x, y) { … }, each name typed as the event declares it. A handler may name fewer values than the event sends, never more: a name past the last one is the new error T22, which says what the event sends. The same holds for an api's hooks and a connection's handlers.

  • Gestures on a component's call (chapter 9). drag:, dragGroup:, dropValue:, dropAxis:, dropInside:, on receive(d), on dragmove(d), on longpress and on swipe written on a component's call land on its root element, as class: and on contextmenu already did. A component whose body is not one element has nothing for them to land on, which is the new error C07.

  • Modal.Title and .closable (chapter 9). Modal.Title { … } (and Dialog.Title) is drawn in the heading in place of title:'s words, so a heading can set a name apart in code; title: stays the dialog's name. .closable puts a close button, named Close, in the heading row. It closes the dialog as Escape does, so on close runs and visible: follows. Both work in the live page, the pre-render and the template engine.

  • Source maps (chapter 39). build.sourcemap was in the config and nothing read it. wf migrate

wf migrate [path] [--check] [--stdout] rewrites every .wf under src/ in place — spelling only: the migrated project builds to what it built before. What needs a decision is reported as a note. --check reports without writing; --stdout prints one file's result.

The registry

src/registry describes every built-in once — its positional prop, props with their types and enum cases, flags, events, slots, parts, attribute families — and the compiler's checks, the linters, the language server's hover and completion, the tree-sitter vocabulary check and the tests all read it. The secondary tone reaches Badge, Text and Icon; Spinner has sizes and no tone.

The type checker

Gradual and structural: everything it cannot resolve is Any, which agrees with everything, so every existing project checks without an annotation, and each annotation — state x: [Todo], a prop's type, a type's fields, resource x: [Deploy] — narrows what it can say. It reports, as errors with hints: a value of the wrong type (T01), a case an enum lacks (T02), a value that may be null read without if let, ?? or a != null check (T04), a field or method a record lacks (T05), a member a store lacks (T06), a list or record as a condition (T07), a for over a non-list (T08), an emit that does not match its event (T09), a call with the wrong arguments (T10), a match with nothing to match (T11), and a bind: on a control of the wrong kind. Specified in spec/TYPES.md.

Motion

The universal props — an animation as a flag (.fadeIn), exit:, .fast/.slow, duration:, delay:, easing:, stagger: — on any element, built-in or the project's own. On a branch's root they are the branch's; anywhere else the element plays its own exit before it is removed, wherever it was. A keyed list slides a moved item from where it was. Router(transition: .fade | .slide, duration:) plays one page out and the next in. transition { } blocks take $token timings. prefers-reduced-motion is honoured by the runtime as well as the stylesheet: no class, no wait.

Compiler diagnostics

Errors now: a parse error, a reference to nothing, a flag, case, part, prop, event, slot or layout nothing declares, an ambiguous flag, a positional argument out of place, a match arm the value cannot take, a loose statement in a render block, a clause out of order, the type checker's findings, and a file in the old grammar. V01 names the flag you meant (` did you mean .center? `); a named argument a built-in does not declare is a warning and is written as an attribute.

Tooling

  • Language server: hover and completion are driven by the registry and the type checker — flags after ., cases after tone: ., $tokens in a style value, events after on, a component's events after emit, the arms a match still lacks, a component's slots, layout: candidates, props not yet written, a record's fields and a list's methods after a typed value; hover shows a flag as the prop it sets and a name's inferred type; go to definition follows layout:.

  • Editors: the tree-sitter grammar is rewritten for the new grammar (a small external scanner reads style values), with the Zed queries and snippets and the VS Code TextMate grammar; every .wf in the repository and in Halyard parses without an error node.

  • Structured edits (EditOp) write the grammar of the file they edit: AddModifier appends a flag, SetStyle writes a raw value.

  • The documentation's wf blocks are parsed by the test suite (tests/docs_parse.rs), so an example cannot go stale.

Breaking changes

6

  • The old grammar is refused. wf build, wf serve, the template engine, the language server and the Node binding read WebFluent 3 only. Run wf migrate.

  • A Button's block of statements is no longer its click handler; write on click { }. The migrator does.

  • A word nothing declares is an error, where it used to be the V01 warning; Alert(elevated) and its V02 are gone with the modifier words.

  • The runtime's public surface is renamed for what each thing does: h→el, condRender→when, listRender→each, showRender→show, wfFetch→fetch beside the new resource, createStore→store, createRouter→router, definePage→page, showToast→toast, bindDialog→dialog, bindPopup→popup, tablist→tabs, offCanvas→drawer; new match, mark, emit. The compiler and the runtime ship together; nothing outside a build's own bundle should have named these.

  • t("key", name: value) never parsed; interpolation takes a map: t("key", { name: value }). The documentation said otherwise.

  • Library: webfluent::parse_source(src, file) is the one way in; Lexer/Parser of the old grammar are #[doc(hidden)] behind wf migrate. Expr::Record is a new expression; sema::check, sema::types::check and sema::lower run between parsing and codegen, and the linters see the lowered program.

Fixed

5

  • A list was rebuilt whole on every change, losing focus, scroll and animation state in items that had not changed; for … by key keeps the nodes of the items that stay.

  • The route table depended on source order; it is now ordered by specificity, then path, whether the Router had children or not.

  • easing: on an element was accepted and ignored; it sets the timing function, and spring, smooth, bouncy, easeOut and the rest mean the same there as in a transition block.

  • A multi-line call that gained motion props from a migrated animate(…) clause had them written on the closing parenthesis's line; they take a line of their own.

  • Lint hints spoke the old grammar (Heading("Page Title", h1)).

Migrating

  1. Install 3.0 and run wf migrate in the project. Read the notes it

prints: each names a file and a line where the migrator could not decide — a modifier word no spelling exists for, an imperative fetch to rewrite as let x = await fetch(…). Commit the result; wf build is byte-identical for a project that needed no notes.

  1. Expect errors that were warnings. A misspelled flag, a prop a

component does not declare, a case an enum lacks: the build stops and says what it takes.

  1. Annotate what you want checked. Nothing is required; `state items:

[Todo] = [] and resource r: [Deploy] = fetch(…)` are where the type checker starts to see.

  1. If anything of yours named WF.* runtime functions — a custom

stylesheet does not, a script in index.html might — rename per the table above.

  1. Zed users: the extension's 2.0 pins the new grammar; the old one

highlights nothing useful on migrated files.

#2.2

19 September 2026

A release about what a built site is like to use and to load. The Halyard demo (https://github.com/monzeromer-lab/Halyard) was put in front of Lighthouse and a screen reader, and everything either one found that the compiler could have prevented, it now prevents; the same site also asked for stylesheets of its own. Halyard's pages went from 63–71 to 87–99 on mobile performance and to 100 on accessibility, with every finding that remained pointed at by wf build. Nothing in this release is breaking.

Added

4

Your own stylesheets

Any .css file under src/ is part of the build: read in path order, bundled into styles.css after the engine's rules and before the rules style { } blocks compile to, minified with the rest. var(--token) reaches every design token. An element names a rule with class:, which adds to the engine's classes rather than replacing them, and follows state:

Card(class: "feature feature--first") { … }
Heading("Forms", h1, class: if loud { "hero--loud" } else { "" })

V02 accepts a modifier class one of these files defines (.wf-alert--elevated makes Alert(elevated) real), in the build and in the editor.

Form fields

Input and Select with label:, hint: or error: become a field: the label is a <label for> the control, the hint and the error are linked by aria-describedby, the error (a string, empty when there is none) is a role="alert" hidden until it has text and sets aria-invalid. The static paint and the client agree, so hydration adopts it.

Input(text, bind: name, label: "Name", hint: "As on your passport", error: nameError)

Accessibility in the runtime

  • A route change settles the reader on the new page: focus moves to its heading (or the main landmark), the viewport returns to the top, the title is announced in a polite live region.

  • Carousel is a labelled region whose slides are groups; it has named previous/next/dot controls, a pause button, stops for reduced motion and hidden tabs, and hides the slides that are not showing from assistive technology.

  • Tooltip opens on focus as well as hover, closes on Escape, and describes its trigger with aria-describedby.

  • Dropdown menus follow the ARIA menu pattern: role="menu" with menuitems, arrow keys, Home/End, Escape, and focus returned to the trigger.

Lint rules

  • A14 — a role: that requires particular children (tablist, menu,

list, radiogroup, …) holding something else. A user component is judged by its root element, and a role given through a prop by what the call passed or the prop's default.

  • A15 — an aria-label that does not contain the control's visible text:

its label, the literals in its block, and what a component in the block renders from its literal props (Kbd(text: "⌘K") in a search button).

  • Every element rule now points at the element's own line and column.

Build output

  • build.minify is honoured at last: the bundle and the sheets lose their

comments and whitespace, and nothing else. Halyard's app.js: 691 KB → 212 KB.

  • build.split (on by default) writes each page as pages/<Name>.js,

linked beside app.js by a static page and fetched by the router the first time its route shows in a single-page build.

  • The stylesheet carries only the component rules the project uses.
  • Literal style { } declarations compile to shared classes instead of

inline styles — one rule for a hundred identical cards, on the static paint before any JavaScript runs.

  • The rules only one page can reach ship in pages/<Name>.css, linked by

that page and loaded by the router before it draws; what the App body or two pages share stays in styles.css. Halyard: 144 KB → 49 KB shared.

  • build.compress (on by default) writes <file>.gz beside every text

output over a kilobyte, with a DEFLATE encoder of the engine's own — within a percent of zlib's default level, no dependency — for hosts that serve a precompressed file when they have one. wf serve sends it, and compresses on the way out what has none, so a Lighthouse run against the dev server measures what a deployed site sends.

  • The static paint evaluates derived values and pure actions at build time,

so a seeded list is painted with its rows rather than left to hydration.

  • Images decode asynchronously; the first on a page is eager with

fetchpriority="high", the rest lazy, unless loading: says otherwise.

Editor support

The Zed extension and the Tree-sitter grammar were rebuilt from scratch and live in this repository (editors/zed, editors/tree-sitter-webfluent). The language server reads the whole project the way wf build does — a store declared in another file resolves, a component called across files is known — and reports positions in the units each client expects.

Fixed

4

  • class: as an attribute replaced the engine's classes; it adds to them.

  • A14 reported a component whose root took its role from a prop as a plain control.

  • wf serve read a query string as part of a file name.

  • The language server matched a document to its project by URL text rather than by path, and could miss a file with an escaped character in its path.

#2.1

19 September 2026

A release driven by building a real application. The Halyard demo (https://github.com/monzeromer-lab/Halyard) — a nineteen-screen product design implemented entirely in .wf — found every place where the language did less than its documentation promised, and a handful of things a design system needs that it had no way to say. Each is fixed or added here, with a test. Nothing in this release is breaking.

Added

3

State and media in style { }

A style block may now hold blocks for how an element looks while hovered, focused, active, disabled, or in an ARIA state, beside its @media blocks:

Button("Save") {
    style {
        background: "var(--brand)"
        hover { background: "var(--brand-hover)" }
        focus { outline: "2px solid var(--focus-ring)" }
        pressed { color: "var(--text-accent)" }
        @media (max-width: 768px) { width: "100%" }
    }
}

States: hover focus active disabled placeholder focus-within current pressed selected checked expanded invalid. The ARIA ones key off the element's own aria-* attribute, so state and paint cannot disagree. These compile into styles.css under a content-hashed class — one rule per distinct block, shared by every element that writes it, and nothing injected at run time (CSP-safe). @media blocks, which used to become a run-time <style>, take the same path.

Attributes by name

A hyphenated named argument is an attribute: Trow(aria-selected: isSelected), Badge("Ready", data-tone: "success"). A value that reads state follows it, and an aria-* value of false is kept as the string "false", which is a real ARIA state. A keyword after the hyphen is fine (data-state:).

Custom properties and reactive style values

style { --edge: color } sets a custom property. Any style value that reads state is now kept in step with it, so style { height: "{pct}%" } moves.

Components

  • A component's block reaches it as children, in both the SPA and SSG backends. AppShell(crumb: "Logs") { … } is one component.

  • Props are live: Chip(pressed: showErrors) repaints when showErrors changes. Declared defaults reach the SPA.

  • A handler written on a component call — the click shorthand or an explicit on:… block — attaches to the component's root element.

Vocabulary and layout

  • Row/Stack/Grid gap: xs|sm|md|lg|xl, align: and justify: (six

values each) are real utility classes in both stylesheets.

  • Modifiers fluid circle multiple ordered xs sm md lg xl header:

List(ordered) is an <ol>, Tcell("Build", header) is a <th scope=col> wherever it is written.

  • Table(caption: "…") gives the table a visually hidden caption; a Tcell

inside Thead is a <th>.

  • Link(to: "/docs", active: "prefix"): links get .active and

aria-current="page" from the router, on the static paint too.

  • Option("value", "Label") submits the value and shows the label.
  • Theme token and property names may have digit-leading segments

(viz-1, radius-2xl).

Config

meta.fonts and meta.stylesheets add <link rel="preconnect"> and <link rel="stylesheet"> to both HTML shells; the CSP policy widens for those origins.

Language

Two-parameter lambdas (a, b) => expr; a keyword after a dot (Array.from); Number, String, Boolean, Map as globals; a map literal as an arrow body; store derived values may read other derived values and actions.

Fixed

18

  • Icon("home") rendered the word "home"; only icon: drew the glyph.

  • IconButton dropped every named argument but icon and label, and the static backends painted the label as visible text next to the glyph. It is the accessible name (aria-label, title) only, and the glyph is drawn once.

  • Progress(value: expr) was painted once and never moved.

  • Lambda parameters inside pages compiled as signal reads (_x()).

  • An action parameter named like another action read the store member (move(step) beside step).

  • placeholder, disabled, src and the other recognised attribute names were set once even when bound to state.

  • A <select> bound to state always showed its first option: the value was applied before the options existed (runtime), and a slot inside a Select component was appended after the value (codegen).

  • An else if chain with a final else skipped every branch.

  • A Slider or Input with both bind: and on:input kept only one.

  • A Button's block that mixed content with an action ran the action at render time; the action statements are its click handler now.

  • A sub-component dropped its style block, attributes and handlers in the SPA.

  • createStore bound derived values before actions, so a derived value that called an action threw.

  • The router never set document.title.

  • wf build did not run the V01/V02 vocabulary lint or the semantic check; it does, with per-file locations.

  • The catch-all page was written to a directory literally named *. It is 404.html at the root, and it addresses its assets from the site root, so a dynamic route under a static build hydrates.

  • wf serve did not serve a pre-rendered <route>/index.html.

  • The heading-outline lints (A11, A12) could not see headings inside components; A03 did not accept aria-labelledby; A13 warned about a white label on --color-primary even when no primary variant was used.

  • In structural mode the sheet stacked every Row under 768px; it no longer paints layout decisions the author did not make.

2.0

#2.0

A release about correctness. The language gained themes and SEO; the output gained the accessibility, responsiveness and search metadata it should always have had. Several long-standing bugs are fixed, and the tests that would have caught them now exist.

This release contains breaking changes. See Migrating at the end.

Breaking changes

4

Themes are written in WebFluent

The four built-in palettes (default, dark, minimal, brutalist) are gone from the compiler. A theme is source now:

Theme Brand {
    token color-primary: "#0F766E"
    token radius-md: "14px"
}

Declare one and it is used; declare several and select with "theme": { "name": "Brand" }. Tokens you do not name keep their baseline value.

dark, minimal and brutalist ship as examples/themes/*.wf — copy one into your src/ and the existing "name" in your config keeps working. A config that still names a removed palette fails the build with a message pointing at the replacement, rather than silently rendering as the default.

theme.mode and theme.extends were declared in config and never read by anything. Both are removed.

Modal and Dialog are native <dialog> elements

They were divs with an .open class, which meant no focus trap, no inert background, no Escape-to-close and no aria-modal. They now use showModal(), so the browser supplies all four. If you styled .wf-modal directly, note that it no longer positions or hides itself — the element does that — and the backdrop is ::backdrop.

Library signature changes

  • generate_css(tokens) / generate_css_with(tokens, builtin) take resolved tokens rather than a theme name. Use themes::resolve_tokens(program, config).

  • render_page_html / render_page_html_studio take a SiteContext instead of five separate parameters.

  • generate_html(config, program) takes the program, for the page metadata.

  • Template::with_theme(name) selects a Theme declared in the template rather than naming a built-in palette.

Fixed

11

  • for loops produced bundles that crashed. The loop bound a plain callback parameter but every reference to it was emitted as a signal read, so any non-empty list threw ReferenceError on first render. wf init -t spa shipped this.

  • Zero-width spaces in every static page. The SSG and template renderers emitted U+200B after every closing tag — invisible in an editor, present in textContent, in copied text and in what a crawler indexed.

  • Heading("x", h1) did not produce an <h1> under wf build. The static renderers switched the tag; the SPA codegen never did, and emitted a wf-heading--h1 class no stylesheet defines.

  • style { } blocks were dropped on nineteen components — every one handled by a dedicated emitter, because styling was applied after the dispatch that returned early.

  • The sidebar rendered transparent — no background at all in structural mode, and surface-on-white behind a 1.23:1 border in the full one.

  • Navigation vanished on a phone. The sidebar was display: none below 768px and navbar links below 480px, with no control to bring either back. Both are off-canvas now, with a toggle, a scrim, Escape-to-close and focus return.

  • Structural mode had no focus indicator at all, and .wf-input / .wf-select removed the outline without replacing it visibly.

  • theme.builtin: "structural" never reached wf build — only the studio honoured it.

  • The language server had not compiled for several releases. Nothing in the repository built it; cargo build at the root builds the root package alone. Its completion list had drifted to 43 missing modifiers and eight invented ones.

  • Link("Home", to: "/") drew a spurious accessibility warning, and both the PDF and slides scaffolds warned on their own first build.

  • PDF images ignored their alt and drew [Image] regardless; Progress(max: 0) rendered a full bar instead of an empty one.

Added

Search and sharing

Set meta.site_url and every page gets a self-referencing absolute canonical, Open Graph and Twitter card tags, hreflang alternates with x-default, and JSON-LD (WebSite, Organization, WebPage/Article, BreadcrumbList). Builds write sitemap.xml and robots.txt.

Page accepts description, image, type and a bare noindex.

Without site_url, tags that need an absolute URL are omitted rather than guessed at — a relative canonical causes problems later.

Accessibility

Tabs carry the full tablist/tab/tabpanel wiring with roving tabindex and arrow keys. Dropdowns report aria-expanded and close on Escape. Toasts and alerts are live regions. Every page has a <main> landmark and a skip link. Animations respect prefers-reduced-motion. Pointer targets meet the WCAG 2.2 minimum of 24×24.

Performance

The type and spacing scales are fluid (clamp()), so a page responds without a media query — and without losing to an inline style { font-size: … }. Images default to loading="lazy" and decoding="async". The bundle loads with defer. The default font stack no longer names webfonts nothing loads.

The static renderer now paints lists and conditionals over seeded data instead of leaving <!--wf-for--> for the client.

Security

"build": { "csp": true } emits a strict CSP and a _headers file. The dev server sets nosniff, Referrer-Policy and X-Frame-Options.

Diagnostics

A13 (theme contrast, checked at compile time because themes are now source), S01–S04 (title, description, description length, duplicate route) and V02 (a real modifier whose class no stylesheet defines).

For tooling

CompiledSite carries the resolved tokens, the declared themes with their spans, flattened diagnostics, and the reason a theme failed to resolve.

Migrating

  1. If your config names dark, minimal or brutalist: copy the matching

examples/themes/*.wf into your src/. Your existing "theme": { "name": … } then resolves to it. The build tells you this if you forget.

  1. Remove theme.mode and theme.extends if present; they are ignored.
  2. If you styled .wf-modal or .wf-dialog directly, re-check it against a

native <dialog>.

  1. Add meta.site_url to get canonical URLs, sharing cards and a sitemap.

Nothing breaks without it; those tags are simply not emitted.

  1. Expect new warnings. S02 fires on every page with no description. None

of them fails a build.
