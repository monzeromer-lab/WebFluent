A site speaks several languages by keeping its text in one JSON file per
locale and reading it with `t("key")`. Switching the locale re-renders
every translated string, flips the document to right-to-left where the
language reads that way, and changes how `format` and `ago` spell numbers
and dates.

## Setting up

In `webfluent.app.json`:

```json
{
  "i18n": {
    "default_locale": "en",
    "locales": ["en", "ar", "es"],
    "dir": "src/translations"
  }
}
```

One file per locale in that directory, flat keys with dots by convention:

```json
{
  "nav.home": "Home",
  "nav.about": "About",
  "welcome": "Welcome, {name}!",
  "items.one": "{count} item",
  "items.other": "{count} items",
  "actions.save": "Save"
}
```

```json
{
  "nav.home": "الرئيسية",
  "nav.about": "حول",
  "welcome": "أهلاً، {name}!",
  "items.zero": "لا عناصر",
  "items.one": "عنصر واحد",
  "items.two": "عنصران",
  "items.few": "{count} عناصر",
  "items.many": "{count} عنصراً",
  "items.other": "{count} عنصر",
  "actions.save": "حفظ"
}
```

A missing file is a build warning; a key missing from a locale falls back
to the default locale, then to the key itself.

## Starting translated

```bash
wf init my-app --locales en,ar
```

starts a project — `spa` or `static` — in those languages, the first the
default: the `i18n` config above, `meta.lang` the default, every visible
string through `t("…")`, a language switch with one entry per locale, and a
file for each in `src/translations/`. The default's holds the starter's
English, which its pages and tests are written in; Arabic holds the
starter's Arabic; any other locale starts as the same English, for you to
translate. Each locale is a language tag (`en`, `ar`, `pt-BR`); `--locales
ar,en` makes Arabic the default, so the page is right to left from the
first paint. From a program it is
`webfluent::init::create_with(dir, name, &Options { template, locales })`.

## `t("key")`

```wf
type User { name: String }

page Home(path: "/", title: "Home", description: "The home page.") {
    state user = User(name: "Sam")
    state items: [String] = ["a", "b", "c"]
    Heading(t("welcome", { name: user.name })).h1
    Text(t("items", { count: items.length }))
    Button(t("actions.save")).primary
}
```

- `t("key")` is the string for the current locale, reactive: every call
  re-evaluates when the locale changes.
- `t("key", { name: value })` fills `{name}` placeholders from the map.
- A `count` picks the plural form the locale's rules give it — CLDR's
  rules, which the browser's `Intl.PluralRules` follows too: Arabic has
  `zero`, `one`, `two`, `few`, `many` and `other`; English `one` and
  `other`; Japanese only `other`. Exactly none is `key.zero` wherever the
  file has one, in any language, so English can say "No files" rather
  than "0 files". Falls back to `key.other`, then `key`.
- A key's forms all come from one language: the reader's, when its file
  has the key at all, otherwise the default locale's — never one form from
  each.
- The static paint resolves `t` for the default locale at build time, by
  the same rules, so the pre-rendered HTML is already in the default
  language, its counts in that language's forms.

## Switching the locale

```wf
app {
    state chosen = "en"
    Navbar {
        Navbar.Brand { Link("i18n", to: "/") }
        Navbar.Links {
            Link(t("nav.home"), to: "/")
            Link(t("nav.about"), to: "/about")
        }
        Navbar.Actions {
            Select(bind: chosen, label: t("nav.language")) {
                on change { setLocale(chosen) }
                Select.Option("English", value: "en")
                Select.Option("العربية", value: "ar")
                Select.Option("Español", value: "es")
            }
        }
    }
    Router
}

page Home(path: "/") {
    Text("Locale: {locale}, direction: {dir}")
    if locale == "ar" { Text("النسخة العربية") }
}
```

`setLocale("ar")` switches; `locale` is the current code and `dir` is
`"ltr"` or `"rtl"`. On a switch, `<html lang>` and `<html dir>` are set.
A locale is right to left when its language is — Arabic, Hebrew, Persian,
Urdu, Pashto, Sindhi, Central Kurdish, Uyghur, Yiddish, Dhivehi, Kashmiri,
Syriac, Aramaic and N'Ko — so `ar-EG` is too. A site whose default locale
is one of them is written `<html lang="ar" dir="rtl">` from the start, before
any script runs. `meta.lang` names a region of the default locale's
language (`en-GB` for `en`); otherwise the default locale is the page's
language.
The built-ins use logical CSS properties (`margin-inline-start`, not
`margin-left`), so layouts mirror without work on your side; do the same
in your own `style` blocks.

An `app` block may declare `state` like a page, as `chosen` above.

## Which locale a page opens in

A page opens in `default_locale`, unless its address carries `?lang=<code>`
for one of the configured locales — `/about?lang=ar` opens the Arabic page.
That is the address the build gives each language in the `hreflang`
alternates it writes for search engines, so a reader who arrives from a
search result in Arabic reads Arabic.

The runtime does not guess from the browser's language, but it remembers
a choice. `setLocale(code)` keeps the code in the reader's `localStorage`,
under `wf:locale`, and every page loaded after that opens in it, on this
visit and the next; choosing `default_locale` again forgets it. A `?lang=`
address opens its page in that language and leaves the kept choice alone.
So a static site, which loads each page afresh, keeps the reader's
language from page to page, and a language switch is a button that calls
`setLocale`:

```wf
app {
    Navbar {
        Navbar.Brand { Link("i18n", to: "/") }
        Navbar.Actions {
            Button("English") { on click { setLocale("en") } }
            Button("العربية") { on click { setLocale("ar") } }
        }
    }
    Router
}
```

Nothing is kept until the reader chooses, so a first visit, and a search
engine's crawler, still get the `?lang=` locale or the default. To start
a first visit from the browser's language, keep whether the reader has
chosen in a store with `persist`, and until they have, apply
`setLocale(navigator.language.slice(0, 2))` from an `effect` in the app.

A static build pre-renders every page once, in the default locale; another
locale is applied as the page loads. For search engines that is what the
`?lang=` alternates are for.

## Numbers, dates and the locale

`format` and `ago` follow the current locale ([chapter 14](14-expressions.md#format-and-ago)):
`format(1234.5, .currency, "EUR")` is `€1,234.50` in `en`, `1.234,50 €`
in `de`; `ago(date)` says "il y a 3 jours" in `fr`. The static paint uses a
table of the common locales' separators and currency symbols; the live
page uses `Intl` and corrects any difference.

## Translating a `Markdown` page or a `.md` page

Text inside a `.md` page is not passed through `t`; keep one Markdown file
per locale and route by a `:locale` parameter, or keep the long-form text
in the translation file under a key and render `Markdown(t("about.body"))`.

## Checklist

- Every visible string goes through `t`, including `label:`, `placeholder:`
  and `aria-label:` values.
- Never build a sentence from parts (`t("x") + name`); use a placeholder so
  a translator can reorder it.
- Give every count its plural forms, even in English, and a `zero` where
  none reads better as a sentence.
- Test with an RTL locale once: alignment, icons that imply direction
  (arrows), any `left`/`right` in your own CSS, and a Latin code or figure
  inside Arabic text, which needs a left-to-right run of its own
  (`direction: ltr; unicode-bidi: isolate`) to keep its parts in order.

## The translations as a table

`wf translations` lists each locale with the plural forms its rules use
and how many keys it lacks, a form it lacks, or a placeholder that differs
from the default locale's; `--missing ar` lists what Arabic lacks and
`--unused` the keys nothing names; `--json` is the whole table, each key
with its message in every locale and every place a `t()` names it.
`--plurals` prints CLDR's rules: every locale's forms. The library has it
as `webfluent::i18n::table`, which also writes one message back into its
file with every other byte as it was.
