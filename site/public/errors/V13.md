# V13 — A deprecated built-in

> A built-in on its way out: it draws as it always has through 8.x and is removed in 9.0; the finding names what replaces it, and `wf fix` rewrites it where the rewrite is exact.

The page: https://webfluent.monzeromer.dev/errors/V13

A few built-ins were near-copies of another, and are on their way out. Each
still draws exactly as it did through every 8.x release, and is removed in
9.0. The finding names what takes its place:

| Deprecated | Write instead |
|---|---|
| `Dialog`, `Dialog.Title` | `Modal`, `Modal.Title` |
| `Dropdown(label: x) { Dropdown.Item { … } }` | `Menu(trigger: x) { Menu.Item { … } }` |
| `Tag("x")` | `Chip("x")` |
| `Toast("Saved").success` | `toast("Saved", tone: .success)`, called where it becomes true |
| `Code(text).block` | `CodeBlock(text)` |
| `CircularProgress(…)` | `Progress(…).circular` |

```wf expect=V13
page P(path: "/", title: "T", description: "D") {
    state asking = false
    Heading("Settings").h1
    Dialog(visible: asking, title: "Discard the draft?") {
        Text("What you wrote is lost.")
    }
}
```

```wf fixed
page P(path: "/", title: "T", description: "D") {
    state asking = false
    Heading("Settings").h1
    Modal(visible: asking, title: "Discard the draft?") {
        Text("What you wrote is lost.")
    }
}
```

`wf fix --code V13` — and `wf migrate`, for a project moving to 8 — makes
each rewrite that is exact: the name, the parts in its block, a
`Dropdown`'s label as the menu's `trigger:`, a `.block` flag dropped. A
`Toast` is rewritten as a `toast(…)` call only at the top of a page or a
component, where it is drawn once; one inside an `if` or a `for` is shown
each time that branch or item is drawn, so the call belongs in the handler
or action that makes it true, which a person writes.

**Fix:** Write the replacement the finding names, or run `wf fix --code V13`.
